# 経路C: AWS 参照実装（準備中）

株式会社クラウドネイティブが**自社サイトで実運用している構成**のサニタイズ版。エンジニア向け。

```
フォーム POST → API Gateway → 同期 Lambda（Turnstile検証 → 記録保存 → SQS送信 → 即200）
SQS → 非同期 Lambda（few-shot取得 → AI分類 → 記録更新・通知・外部連携を並列）
     + DLQ（3〜5回失敗で退避・アラーム付き）
Slack ボタン → フィードバック Lambda（署名検証 → 修正記録 → few-shot 還流）
シークレット: Secrets Manager / 検知: CloudWatch メトリクスフィルタ + アラーム
```

## 状態

このテンプレートは**ステップ3で追加予定**（公開前マスキング監査と同時に整備する）。

## この構成を選ぶ理由（経路Aとの違い）

- SQS + DLQ による確実な再処理と退避（docs/PITFALLS.md C 章の数値設計を含む）
- CloudWatch メトリクスフィルタ + アラームによる本格的な検知（同 F 章）
- Slack ボタン（署名検証・IDOR 対策込み）での修正 UI（同 D 章）
- CRM・タスク管理などの外部連携のオーケストレーション

小規模なフォームには過剰。まず経路Aで始めて、必要になったら移行するのが推奨。
